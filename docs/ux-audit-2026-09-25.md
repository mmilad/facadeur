# Facadeur editor — UX / maturity audit

**Date:** 2026-09-25  
**Scope:** `@facadeur/editor` shell only (stage chrome, inspector IA, viewport/breakpoint affordances). No product redesign; observations and suggested directions only.  
**Method:** Local `pnpm dev` (Vite, specimen catalog), hands-on walkthrough (project tree, layers, stage pan/zoom, selection, Properties scroll depth, Design → Tokens/Schriften, Specimen page multi-viewport, Base vs viewport override), plus code review of `viewports.ts`, `viewport-bar.tsx`, `panels.tsx`, and stage CSS.

**Reference screenshot (user):** TEXTAREA atom, `control` layer selected, focus mobile · 375, long Bindings stack — attached to the audit request.

---

## Executive summary

The editor’s **data model and multi-viewport rendering are ahead of the shell**: breakpoints rebuild from document/design settings, style and token overrides respect focus + Base/viewport mode, and the specimen page proves side-by-side frames. The **presentation layer still reads as a prototype**: viewport chrome is a bare rounded card with a floating label, the Properties rail is one undifferentiated scroll without section navigation, and breakpoint **management** exists only as `setBreakpoints` in the core — not in UI. Duplicate Tokens/Fonts entry points (left Design tree + right inspector tabs) add noise while Properties remains the longest path.

### Code anchors (P0)

- Stage DOM: `packages/editor/src/viewports.ts` — `viewport-frames` → `viewport-frame` → `viewport-label-slot` + `viewport-screen` → iframe mount.
- Stage CSS: `packages/editor/src/styles.css` — `.viewport-screen { border-radius: 16px; overflow: hidden; … }`; label absolutely positioned in `.viewport-label-slot` with no chrome wrapper.
- Inspector stack: `packages/editor/src/ui/panels.tsx` — `Properties()` single `<div className="properties">` with no subsection nav; `Inspector` still exposes top-level tabs.
- Breakpoint commands: `packages/core/src/commands.ts` — `setBreakpoints`; **no** call sites under `packages/editor/src/ui/`.
- Viewport editing: `packages/editor/src/ui/viewport-bar.tsx` — focus copy + Base / viewport toggle only.

## Verified behaviors (keep / working)

- Multi-viewport **synced render** from shared stores; breakpoint rebuild when `page.settings.breakpoints` signature changes (`viewports.ts` tests).
- **Focus viewport** drives `writingBreakpointId` for style, layout, and token overrides (`viewport-edit.ts`, shell test for tablet override + Reset).
- **Design → Tokens / Schriften** opens the correct inspector panel and keeps specimen page open (`shell.test.tsx`).
- **Layers** tree, double-click drill-in to master, drag-from-tree insert rules enforced.
- Canvas **pan/zoom** and stage hint document basic navigation.

## Out of scope / explicit keeps (do not regress)

| Decision                                                                                                                                                                                | Rationale                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **Tokens and Fonts stay under Project → Design** on the left; they are **not** Properties sub-tabs in the intended Shell IA.                                                            | Matches project tree model and tests; right-rail Tokens/Schriften tabs are **legacy duplication** (P1-1), not the long-term pattern. |
| **Node style is always Base** (copy in ViewportEditBar) — viewport mode applies to declarations/layout/tokens on the style owner, not ad-hoc per-node breakpoint nests for every field. | Documented product rule; audit does not propose changing the style model.                                                            |
| **Token-based spacing in authored documents** (e.g. `{input.padding.x}`) remains valid; P0-2 is about **editor preview chrome**, not replacing design tokens in the DSL.                | User asked for free **px** on the **inner iframe / viewport screen**, not token removal.                                             |
| **No redesign** of control widgets (color, typography, layout controls) in this audit.                                                                                                  | Maturity focus is IA and stage chrome; control internals are out of scope.                                                           |
| **Commands-only breakpoint editing** in JSON remains acceptable for power users until UI ships.                                                                                         | P0-4 is about missing UI, not removing `setBreakpoints`.                                                                             |

## Suggested fix ordering (for implementers)

1. **P0-1 + P0-2** — Stage chrome wrapper + px preview inset (visual win, isolated from DSL).
2. **P0-3 + P1-1** — Properties section nav; remove or hide duplicate right-rail Tokens/Schriften tabs.
3. **P0-4 + P1-3** — Breakpoint list UI + stage breakpoint strip tied to focus.
4. **P0-5 + P1-8–P1-10** — Shell polish (language, zoom, dirty state).
5. **P1-5, P1-6** — Properties information architecture (order/collapse).

## Appendix — Properties section order (TEXTAREA, `control` node selected)

Observed top-to-bottom in Properties (2026-09-25 build):

1. ViewportEditBar (focus + Base / mobile is Base)
2. Node id (`control`)
3. Type / Document kv
4. Name, Tag
5. Attribute fields (`readonly`, `tabindex`)
6. **Bindings**
7. **Variant styles** (if variants defined — axis layers)
8. **Style** (style block declarations for node — atoms use root style block paths)
9. Per-node **style property fields** (`StyleFields`)
10. **Layout**

Root selection additionally inserts **Fields**, **Variants**, **Component** style block sections above or among node sections — substantially longer scroll.
